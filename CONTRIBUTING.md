# Contributing

Use synthetic endpoints such as `example.com` or a local test server. Never add real account identifiers, captured cookies, private IP addresses from your environment, local usernames or credentials to fixtures.

Run:

```powershell
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
npm ci
npm run test:ui
python scripts/export-source.py --check
```

Electron smoke checks require an already running Librium core. They use separate Electron profiles under `target` and must never terminate the core used by the main application. Proxy probes write synthetic requests into the currently running history; use an isolated `LIBRIUM_DATA_DIR` for testing.

The desktop/core contract is `desktop_api: 1` plus the required capability flags in `desktop/core-client.cjs`. Keep revision 1 for compatible additions; change the revision when breaking the existing contract and update both sides together. Client checks use owned ephemeral HTTP servers to reject missing/future/incomplete contracts before history reads, verify token staging and block requests after failed negotiation. The real Electron startup check injects an ephemeral old core and asserts no window, history request or shutdown POST; it never binds the user's core port.

Direction checks cover sent messages older than a full received-only page, multi-page direction results, MessagePack/type combinations and invalid API directions. The sandboxed UI finds one client message before 130 server replies, pages received messages, verifies cursor reset on direction changes, checks hidden-panel explanations and wraps the controls at the minimum window width. JSONL export still includes both directions when the UI selects only sent messages.

UTF-8 search/view tests share vectors for BOM handling, Cyrillic, invalid bytes and an incomplete trailing code point. Rust reopens a synthetic history with matches older than 100 messages and verifies text / UTF-8 modes, kind filters and Unicode lowercase matching. The sandboxed UI inserts 135 synthetic messages, finds old Cyrillic text / binary JSON, checks partial-prefix rendering without replacement characters and verifies that Hex retains the original trailing bytes.

`test:ui` checks paged WS JSONL, raw bytes / truncation, backpressure, malformed or deleted pages, browser save / abort and atomic file replacement in an owned `target/ws-export-test-*` directory. The desktop test exports all 132 synthetic messages while a filter shows one, checks native cancellation, rejects invalid IDs and preserves an existing file after a non-WS export fails. Expected export IPC errors in these negative checks are intentional. Rust checks verify a fixed upper message ID while new messages arrive, multi-page order, empty sessions and archive clearing.

`powershell -NoProfile -File scripts/test-network.ps1 -Suite desktop` runs the main-process, sandboxed desktop and proxy checks against an owned isolated core. The source-filter check inserts identical URLs with different capture sources, verifies source selection and an empty match, reloads the actual window to verify native filter-session persistence, and removes the source chip to restore all matching rows. Rust checks cover source filtering beyond the first page and migration of legacy source metadata.

For a focused Chromium check, run `powershell -NoProfile -File scripts/test-network.ps1 -Suite cdp`. It uses the same isolated core and port ownership checks; the default suite still runs every network check. Pending-handshake scenarios hold the server's upgrade response, verify saved attempts on target close / detach / transport loss without a fabricated status 101 or open message session, then allow the surviving application connection to finish after capture stops. A queued browser attempt may expose only its URL before headers are sent; tests distinguish that state from a request received by the server.

For the CDP, Node.js main-process, WebSocket desktop and proxy checks, `npm run test:network` builds and starts an isolated test core, runs the request-body, repeated-startup, ws-library, startup-watchdog, startup-capture, launch-target, observer, CDP, main-process, desktop and proxy checks and stops only that core. It refuses to run if ports 3000 / 8080 are already occupied. History and logs stay under `target/network-smoke-*`; test Electron profiles and synthetic projects also stay under `target/`. CI runs this command after the Rust checks.

The repeated-startup check alternates twelve paused startups and early live attaches with one persistent synthetic Electron profile. It verifies first messages for paused startup and subsequent HTTP / WS for live attach, where the Node event loop must be ready before Network.enable. The startup checks verify the first main-process HTTP response and text / binary WS messages in SQLite, setup failure, transport loss while paused, an unconfirmed start, manual `--inspect-brk`, and the independent watchdog after its owner exits. They also check that a different PID is never released. The desktop test verifies the saved startup preference and rejects non-boolean IPC arguments. To check the watchdog against a packaged Electron executable, set `LIBRIUM_TEST_WATCHDOG_EXE` to the unpacked `Librium.exe` and run the watchdog smoke.

`test:cdp` starts a hidden synthetic Electron window with a loopback debugging port (19333), captures HTTP and WebSocket through the real CDP collector and authenticated core API, and verifies text, binary, truncation and detach behavior. It does not launch Majestic or use real account traffic. The core must be running with the current source changes. `test:ui` also checks the WebSocket protocol analyzer, including fixed MessagePack specification vectors for every type family, exact 64-bit integers, duplicate/non-string map keys, invalid UTF-8, malformed input and size/depth/node limits. `test:ws-ui` verifies explicit MessagePack selection and parse errors through real SQLite rows in the sandboxed renderer.

`test:main-capture` launches a synthetic Electron target with separate browser (19337) and Node.js (19338) inspectors. It checks simultaneous capture, source labels, POST request / response bodies and unavailable native http upload notes, http requests, original gzip / binary bytes, bounded previews, failed requests, Node WS text/binary/Blob/9 MiB messages without duplicate handshakes and detach. It also verifies ws loaded after attaching, actual SQLite text/binary/Blob and reassembled fragmented messages, PING/PONG, option getters/callbacks and method cleanup after inspector loss. The observer smoke also checks concurrent sockets on the same URL, UTF-8 truncation, send semantics and cleanup on detach / lease expiry. `test:ws-ui` verifies the source selector, Node.js gzip rendering, availability notes and invalid source / port rejection in the real sandboxed renderer. Expected IPC rejection errors in this test are intentional.

Third-party dependencies retain their own licenses. Do not add copied code, graphics or traffic samples without checking permission and attribution requirements.

`Summary.ws_role` is optional typed metadata (`client` / `server`). It survives history restore, restart, details, WS summary and JSONL. Proxy upgrades and Chromium / Node client events supply client role; accepted ws server events supply server role. Never backfill roles from URLs or x-librium headers; legacy / unmarked records stay unknown. Ingest rejects roles on non-WS HTTP exchanges, while explicit WS attempts may carry a role before status 101. History search accepts `ws_role` as empty, client, server or unknown, applies kind=ws before pagination, and intersects it with other predicates. Unknown matches absent/null metadata only. Invalid search roles return 400; invalid typed capture enum values are rejected by JSON extraction (422). Desktop requires `ws_roles`.

The partial JSON role index also marks the one-time migration of URL-only ws:/wss: attempts into WS kind; this changes classification only, never assigns a role or alters payloads. Filter sessions retain optional `wsRole` in version 1; older sessions default to all roles. Tests cover role pages / anchors / combinations, missing legacy metadata despite a server header, URL-only attempt migration, restart / export, real client and server producers, invalid capture data, saved UI sessions and role-chip reset. `ws-role-ui-smoke.cjs` deliberately places WS entries behind more than one full page of HTTP records.

The ws observer captures both client sockets and new server peers. Server `handleUpgrade` callbacks are wrapped before application code runs, including noServer bridges that never emit connection. Preserve callback receiver / arguments / return / exceptions; headers are copied after application headers listeners have run. Connection-event fallback must not duplicate a peer. Role is relative to the inspected process; copy real request and response headers and add the internal role annotation before wire headers. Never fabricate a URL for a pre-existing server peer whose request is unknown. Both server emit and handleUpgrade wrappers must be restored on detach / lease expiry, without replacing later application changes.

Run main-process integration through `npm run test:network` (or `scripts/test-network.ps1 -Suite desktop`). The runner generates an isolated localhost leaf certificate with the `ws-fixture-cert` Rust example under its owned target directory; no user CA private key is used. Server tests exercise WS and WSS manual upgrades, immediate responses, negotiated protocol / final headers, same-URL peer isolation, fragments, bounded binary previews, PING/PONG and SQLite direction / close metadata. The library smoke separately checks callback receiver and cleanup. The source tree contains no fixture private key.

Unpacked byte save uses the dedicated `save-ws-inflated` IPC with only source IDs and validated codec / range parameters. Native code fetches and validates a fresh scoped inflate result before the save dialog; renderer-supplied output bytes and file paths are not accepted. `inflateRequest` / `inflatedPayload` share range, response, canonical Base64 and 64 KiB validation with the browser download path. The binary filename identifies source IDs, codec and compressed range. Use the existing atomic `writePayload`, shared `wsMessageBusy` guard and `wsMessageTask`; shutdown must wait for an in-flight unpacked write just as it waits for a source payload write. Browser download uses the already validated view snapshot and reports that download started. Tests cover cancellation, exact empty / binary / 64 KiB output, source deletion / wrong scope, invalid IPC parameters, write failure cleanup, concurrent-save rejection, stale UI replies and quit completion.

`GET /api/traffic/{id}/ws/{message_id}/inflate?codec=gzip&offset=0&length=123` explicitly decompresses an archived BINARY range; offset defaults to 0 and length is optional. It uses the existing authenticated, message-scoped lookup and a blocking worker after releasing the history mutex. Unknown query fields / codecs or out-of-limit bounds return 400; missing/scoped-out source messages return 404. A valid operation returns `{ok:true,codec,offset,length,size,base64}` or `{ok:false,error}` for unavailable/partial data, invalid streams, checksum failures, trailing data or output above 64 KiB. No partial decompression results are exposed. Input and output are bounded to 64 KiB. An explicit length allows a fully saved range inside a partial source. gzip accepts consecutive members; zlib / raw DEFLATE require one complete stream and consume all selected bytes. This is payload analysis, not WebSocket extension negotiation or context-takeover decoding. Desktop requires `ws_inflate`.

The decompressed view is separate from the source inspector. Format changes reuse the validated result; copy acts on the displayed decompressed data. Do not replace the source message/payload or alter raw save, search, comparison, summary or export. Close / new-source generations reject late responses; validate canonical Base64 and output limits in the renderer as well. `ws-inflate-smoke.cjs` exercises the real authenticated API, IPC allowlist and renderer using Node-zlib-generated independent fixtures, including gzip members, all codecs, limits, checksums, incomplete/selected ranges, bad queries, source-ID isolation, safe text rendering and exact original byte save. Rust tests truncate every fixture at each byte boundary and check exact-limit output. JSDOM also checks stale / malformed / oversized replies and parent-close cleanup.

`numericValues` reads fixed-width integer / IEEE float candidates from the original saved WS bytes at the absolute inspector selection offset. It honors typed-array byte offsets and unaligned positions, bounds input to 64 KiB, and returns null when a type's full width is unavailable. Never zero-pad missing bytes or convert 64-bit integers through Number; display and copy their exact decimal strings. Preserve float -0, NaN and infinities. These interpretations are local view data and must not enter raw storage/export. Tests cover fixed LE/BE vectors, uint64 max / int64 min, float special values, array subviews, last-byte bounds, search / jump / range independence, exact copy and per-message cleanup. The native decode inspector smoke additionally exercises the numeric panel and captures its layout.

The WS inspector's binary decode range is a local presentation setting. `analysisRange` derives a bounded BINARY view; never mutate the archived message or the inspector's source payload. With an empty length it preserves source truncation and remaining size. An explicit positive length must fit entirely in saved bytes and describes a complete selection, even inside a partial source; always retain the source's partial label in the UI. This derived view is never evidence of a complete source message and must not be saved or exported. Apply it only to Auto / JSON, MessagePack and Protobuf. Hex, raw views, search-match offsets, byte save and comparison remain relative to the original packet. Protobuf field offsets are relative to the selected start. New-message loading resets both bounds. Validate both before changing applied state, and clear both fields' native custom validity when either is edited. Unit, JSDOM and real renderer checks cover header / trailer exclusion, partial source labels, exact-end and zero-start ranges, invalid-input correction, copied view and exact original bytes saved through IPC.

WS search accepts `kind: "DATA"` (TEXT / BINARY) and `kind: "CONTROL"` (PING / PONG / CLOSE), in addition to individual kinds. These are query groups, never stored message kinds. The shared SQL predicate applies to matched counts, cursor pages and the older-page check before pagination; retain the same semantics with direction and text / decoded / byte searches. CONTINUATION remains outside both groups. Desktop requires `ws_kind_groups`. `ws-kind-groups-smoke.cjs` uses the actual sandboxed renderer and owned core to check old data behind 241 controls, pagination, direction, cursor reset, UTF-8 / byte search, Engine.IO TEXT classification and reachable message content in a short window.

The proxy suite also runs `scripts/ws-control-smoke.cjs` against owned loopback peers. It checks exactly one binary PING/PONG exchange per endpoint, unsolicited PONGs, subprotocol negotiation, UTF-8 split across fragments with interleaved controls, 80 KiB binary messages, normal close and exact SQLite control payloads / bounded previews. Rust transport tests separately cover invalid masks and lengths, malformed upgrade responses, preserved HTTP refusals, cancellation cleanup, TLS trust rejection and HTTP upgrade read-ahead. `src/ws_transport.rs` uses split frame readers with automatic PONG / CLOSE disabled; do not reintroduce endpoint-generated control responses in the relay or cancel a frame read while keeping its connection alive.

The pause UI smoke delays automatic list, detail and WS responses, then checks pause/resume generations and late errors. Manual inspection remains available while paused. The sandboxed WS integration also verifies that capture persists new messages during a viewer pause and displays them after resuming.

Byte comparison pins one bounded 64 KiB snapshot in renderer memory, never localStorage or disk. Compare only equal offsets: changed counts cover the common saved prefix; bytes saved in only one record are separate from proven differences. Partial missing bytes render as `??`, complete EOF as `--`. The pure helper scans at most 64 KiB and retains all contiguous difference regions, including 32768 alternating regions. The UI renders a maximum 256-byte context window and navigates every region without creating an unbounded DOM. Tests cover exact counts/ranges, empty and unequal lengths, partial unknowns, offset / region navigation, inert ASCII, pin/reset/close, cancelled and confirmed history clear, and native narrow-window layout. Clear history must also close inspectors and release the current window's pinned snapshot.

The per-message inspector reads the existing scoped message endpoint. Its Hex view renders every saved byte (4096 lines at 64 KiB), independently of the shared pane preview budget. `ws-inspector-smoke.cjs` reproduces a tail match beyond line 3000, checks exact byte / ASCII marking, decimal / hex offsets, return to match, copy / save, empty messages, stale asynchronous errors, retry and inert text. Native integration checks the actual tail row is in view, format switching and exact content via the sandboxed preload; clipboard writes are intercepted by the fixture. Keep decoded-view rendering and clipboard limits bounded, never infer missing bytes from a reported full size.

Hex WS search is byte-aligned and searches saved Base64 payloads for all message kinds, including partial prefixes. JS validation and Rust normalization share `hex-search-vectors.json`. The bounded KMP matcher handles repetitive patterns in linear time; queries are limited to 4096 characters and previews to 64 KiB. Search-page `match_offset` is ephemeral, zero-based and refers to the first byte match; never persist it or include it in raw exports. Tests cover archived matches, text versus raw bytes, directions, truncated prefixes, invalid syntax, whitespace, partial-byte false positives, offset accuracy, and local validation without an API call. Desktop requires `ws_hex_search`.

The common WS stream preserves ascending message record IDs; do not sort it by wall-clock timestamps or infer request/reply pairs. The UI smoke uses backwards timestamps to verify ordering, both directions, copy, preference persistence and the transition to handshake tabs. Native integration checks all 100 messages in a page against the API, an older page, direction-filter cursor reset and view preference after reload. Switching views must not change filters or the archive cursor.

Per-message payload saves use `GET /api/traffic/{exchange}/ws/{message}` scoped to both IDs, with the `ws_message` desktop capability. `ws-message-smoke.cjs` verifies canonical Base64, exact binary / UTF-8 / empty / partial bytes and atomic replacement failure cleanup. The pause smoke checks the browser download through the authenticated endpoint. Native integration checks the actual message buttons, chooser cancellation, default partial/text filenames, old messages, and invalid / foreign IDs. Shutdown waits for an in-progress native payload write. Keep the 3000-line pane preview budget when changing message cards; byte saving must not depend on formatted or truncated DOM text.

`GET /api/traffic/{id}/ws-summary` is a manual snapshot over the whole recorded session. The grouped scan is deliberately separate from periodic WS polling. Tests cover all Base64 padding lengths, empty/control payloads, full versus stored sizes, partial records, out-of-order timestamps, restart / clear, empty sessions, and finite sums above SQLite's integer range. Desktop integration checks authentication, non-WS rejection, filter-independent totals, manual refresh during capture, and plain-text rendering. The pause smoke also checks stale summary responses after reopening and retry after deletion errors. Desktop requires the `ws_summary` capability.

Protobuf wire decoding is explicitly selected and schema-free. Keep the JS renderer and Rust SQLite decoder aligned through `scripts/protobuf-vectors.json`: all wire types, exact uint64 strings, repeated fields, matching groups, invalid UTF-8, malformed tags / lengths / varints, and size / field / group-depth limits. LEN payloads must not be guessed as messages or packed scalars. Search checks an old Unicode match beyond the latest page and excludes malformed / truncated records. The sandboxed renderer checks the real search endpoint, exact 64-bit values, plain-text rendering, and partial-message notes. Update the `ws_protobuf` capability together with both sides of this contract.

For proxy-only regression work, run `powershell -NoProfile -File scripts/test-network.ps1 -Suite proxy`. It uses the same owned core and isolated history as the full runner. The close summary keeps the first observed CLOSE frame; both frames remain in the message history.

WebSocket close metadata is optional `{code, reason}` in capture `end` events and WS pages / initial JSONL session records. The `ws_close` capability is required by the desktop so an older core cannot silently discard it. Tests cover legacy three-column session tables, persistence after restart, received proxy CLOSE frames, actual Node native / ws library close events, plain-text rendering and JSONL export. The ws library smoke checks loaded / lazy CJS / ESM copies of ws, compression, Blob and fragmented binary receive modes, 9 MiB previews, simultaneous identical URLs, unchanged option getters and callbacks, later application method replacements, lease expiry and the 8 MiB fragment limit across 129 live client connections. The application must continue sending after that limit stops observation.

The request-body checks verify exact Node inspector ID association, UTF-8 / binary view previews, empty versus unknown bodies, the 8 MiB limit and cleanup. The live Electron check sends concurrent POSTs to one URL and verifies captured bytes against hashes computed by the receiving server, including streamed and 2 MiB bodies, aborted uploads and responses sent before upload completion. CDP pair lookup is an explicit authenticated GET `/api/traffic/{id}/ws/{message_id}/cdp-related` requiring `ws_cdp_related`. The scoped source must exist (404 otherwise); malformed IDs return 400. Full original UTF-8 payloads only, no JSON-RPC / notification / derived payload inference. Numeric CDP ID, exact optional sessionId and opposite directions define candidates within one WS session. Only one command followed by one response is paired; reuse / duplicate responses / reversed order are ambiguous, without heuristic matching. Counts cover the archive, links are capped at 20 per kind, latency is capture-time delta only when nonnegative. The blocking scan owns a read-only WAL snapshot outside the shared history lock, allowing capture writes to continue. UI rejects stale replies after navigation, format / range changes or close.

Structured WS search formats `cdp_method` and `cdp_id` require `ws_cdp_search`. They share the strict complete-original CDP parser with pair lookup; method search additionally permits valid notifications without ID. Method substring matching is case-sensitive; ID matching is exact after ASCII whitespace / leading-zero normalization and rejects invalid / unsafe ID queries with HTTP 400. The deterministic SQLite function runs before pagination / cursor / direction / kind predicates complete the query. Empty query retains the existing unfiltered behavior. Shared `cdp-id-vectors.json` covers frontend / backend validation, and archive tests cover nested false positives, non-CDP JSON, partial data, events, UTF-8 BINARY, restart, counts and old pages.

JSON field search uses WS format `jsonpointer` plus `pointer`, gated by `ws_json_pointer`. Path validation is shared by frontend vectors and Rust; UTF-8 bytes <=2048, <=64 segments, RFC 6901 escapes, no URI fragments. `WsFilter` keeps old search wrappers compatible. The SQLite predicate uses argument 2 as pointer in this mode and as empty-query selector otherwise; argument 3 remains needle. Empty JSON needle means path existence, including root, null and empty string. Matching uses decoded strings or exact raw JSON lexemes (serde_json raw_value) and case-insensitive substring search. Referenced duplicate object keys are ambiguous, absent / invalid / partial inputs never match. Complete 64 KiB original TEXT / BINARY only; derived ranges are excluded. The optional field_preview in search replies is capped at 160 Unicode characters with an ellipsis, is rendered inertly, and is not written to message / export storage. Cursor reset and stale guards include pointer changes.

WS JSON pretty printing uses numeric reviver context.source with JSON.rawJSON to preserve exact numeric lexemes, including huge integers, non-finite-after-JS-parsing exponents and negative zero. Without both engine features any numeric document falls back to its original JSON text. This also applies to UTF-8 binary / Engine.IO / Socket.IO display and never changes archive bytes. Tests cover exact / fallback output and native field-preview / formatted-body consistency.

All WS message searches, summaries and CDP pair reads go through read_ws: two shared permits, a read-only deferred WAL transaction and spawn_blocking outside the capture mutex. The permit is owned by the blocking closure until it finishes, including after caller disconnection. Every reader registers the same deterministic WS scalar functions as the writer. Counts, matching rows and older-page checks share one snapshot per response; subsequent requests see new writes. A gated worker test holds a real snapshot, proves try_lock and a capture write succeed before releasing the reader, checks stable old results, then exercises the fresh API response. Browser / desktop UI coalesces identical pending WS queries by connection, query and refresh epoch, removes them on success / failure and rejects stale errors as well as stale results. Desktop allows 30 seconds for archive reads while retaining the normal short timeout for other endpoints.

The WS viewer request scheduler bounds distinct active message reads to two and retains one latest queued descriptor. A new desired key supersedes a different queued key, resolving skipped callers with a null sentinel; loadWs never renders that sentinel. Identical active / queued queries share the promise. Completion cleans the map before resolving callers and starts the still-current queued request; a queued descriptor revalidates selection, cursor, filter / pointer, epoch and pause state before dispatch. Already-sent reads complete normally and stale results / errors remain ignored. Deterministic UI tests cover 30 rapid changes, shared queued requests, slot release on success / failure, pause, returning to an active query and fresh reads after completion. Native IPC tests gate two reads, verify only the final query dispatches after release, and ingest traffic while viewer requests are pending.

`ws_json_fields` gates authenticated GET `/api/traffic/{id}/ws/{message_id}/json-fields`, scoped via ws_message and the bounded read_ws worker. Invalid IDs return 400, missing / wrong-session source 404; unsupported original JSON returns supported:false. json_pointer::inspect preserves raw numeric lexemes, traverses original-order object members / arrays, escapes pointer segments, caps 256 rows / 64 levels / 2048-byte paths / 160-scalar previews and marks limited output. Duplicate decoded keys are collapsed into one ambiguous, unsearchable row; their descendants are not guessed. Inspector table uses text nodes only; copy path / search actions, pending state, retry and late-response guards are scoped to the parent message. The search handoff selects the source WS connection, clears needle, sets JSON pointer / DATA / both directions and reuses the existing archive search. Partial / derived-range sources are disabled. Unit / native tests cover bounds, exact numbers, pointers, duplicate keys, inert previews, clipboard, cross-selection search, error / retry / close and narrow layout.

`ws_json_values` gates authenticated GET `/api/traffic/{id}/ws-json-values?pointer=...` via read_ws. Path validation precedes work; invalid ID / pointer is 400, missing / non-WS session 404. `librium_json_scalar` returns a typed key preserving decoded strings / raw numeric lexemes; invalid / absent / duplicate-path / partial / non-scalar values are SQL NULL and excluded. A materialized extraction CTE feeds grouped counts, direction counts and window aggregates before top-100 LIMIT: matched / distinct / excluded / other totals cover the full archive. Groups are case-sensitive and typed, numeric spelling is preserved. UI ignores viewer predicates for this manual snapshot, renders inert 160-scalar previews, copies complete values, retains totals on copy, supports error / retry / close and read version guards. Tests cover >one page, 128 distinct groups, top-100 remainder accounting, exact numeric types, restart / read-only registry, full copy, native scope / path validation and minimum-window layout.

`ws_json_exact` adds optional WsSearch.exact {kind,value}, where scalar value is always a string carrying decoded string data or original number / boolean / null spelling. Validation rejects unknown kinds, noncanonical numeric whitespace, invalid literals, >64 KiB UTF-8 values and mixing exact with another format / nonempty substring needle. The bound typed scalar key is compared before count / pagination / cursor predicates. Existing wrappers and GET queries remain compatible. POST `/api/traffic/{id}/ws-search` is the same read-only query processor with JSON body, avoiding URL limits for large scalars. Desktop IPC permits a bounded object body only for that POST route; GET / DELETE reject bodies. UI stats links expose a removable exact chip, clear on text / pointer / format / connection changes, preserve intersections and use POST through the bounded request scheduler. Queued deduplication updates the current consumer validity callback so reselecting the same typed value does not dispatch an obsolete descriptor. Tests cover typed / case / number spelling, >one page, old records, partial / duplicate exclusions, restart, 20 KiB IPC body, stale errors, chip lifecycle and narrow existing controls.
